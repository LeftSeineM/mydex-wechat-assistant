## 原型使用

双击 `start.cmd` 打开面板。可以保存目标群、助手昵称，使用模拟群和真实 Codex 调用检查触发逻辑及回答效果。真实微信区域保持未连接，不需要继续扫描旧二维码。

`WECHAT_LAB_ENABLE_WEB_RESEARCH=1` 仅为保留历史代码的显式研究开关，默认不设置。本项目当前路线不再依赖它。

收到通道消息后计划按群 ID 和精确群名筛选，仅处理新 @ 文本。初始化历史作为基线；忽略自身消息；同名群拒绝自动选取；默认生成草稿；发送结果不确定时不自动重试。这些逻辑已有测试，但尚缺真实消息通道验收。

工具与结果：

- `inspect_native.py`：读取磁盘 PE 的导入、延迟导入、导出、关键字符串和候选引用。不加载被分析 DLL，不读取进程或账号数据。
- `trace_native.py`：进一步定位发送、同步字符串的代码引用。产物中的地址是候选，不能直接作为已验证函数接口调用。

- `research/analyze_abi.py`：固定客户端 SHA-256，从 PE 异常展开表确定函数边界，生成函数反汇编、函数哈希、直接调用关系及虚表候选。无展开记录的少数叶函数采用人工核查过的显式边界。

- `research/verify_static_findings.py`：直接核对磁盘机器码、虚表指针与类型字符串。本轮 27 条关键断言、63 个函数哈希全部匹配；输出 `.local/abi/verified-findings.json`。这项验证不触碰客户端进程，不验证在线通道。
- `.local/abi/profile.json`：带版本校验的静态证据。所有入口均标记 `abi_verified: false`、`sending_enabled: false`。
- `research/recovered_sync_4_1_15_13.proto`：从解析与序列化代码重建的 4 层同步数据结构。保留未知字段名，未假定必填性，也未用真实消息验证；不是可登录或可收发的独立协议实现。
- `.local/native-audit.json`、`native-traces.json`、`native-ports.json`：本地研究证据；不表示群接入成功。

### 静态还原结果

以下都是当前 DLL 的相对地址（RVA），不是可直接调用的接口：

- 文本消息工厂 `0x6f4c70` 分配 `0x7a8` 字节，其中前 `0x10` 字节是共享控制块，对象本体 `0x798` 字节。构造函数 `0x766680` 与发送封装 `0x54b02f0` 交叉支持正文位于对象 `+0x758`、接收方字符串位于 `+0xb0`、类型字段位于 `+0x118`。这是发出文本的布局，不能套用到所有收到的消息类型。
- 发送封装的 RDX 指向包含接收方字符串及正文字符串的请求（后者位于 `+0x20`），不是裸字符指针；R9 是会被转移所有权的回调包装。R8 附带字符串的用途尚未完全确定。
- 已连出静态调用链：`0x54b02f0` 构造任务闭包 → 虚表 `0x9805968` 的调用入口 `0x54b1e10` → `0x178f040` → `0x178f100` → `0x1793c90` → 实测命中的 `0x17f3750`。第一段是闭包与调度关系，其余为直接调用；尚未验证线程、异常路径和释放规则。
- `0x2dbd700` 保存退出登录回调；对应闭包产生 logout 失败结果。它不是发送入口。`0x179cb90` 提取发送结果，不能当成发消息函数。
- 接收侧从磁盘类型名 `micromsg.NewSyncResponse` 定位到虚表 `0x8fc0d48`，解析函数 `0x106fb10`、序列化函数 `0x10700b0`。两者交叉显示 7 个字段；字段 2 嵌套 `micromsg.CmdList`，字段 4 嵌套 `micromsg.SKBuiltinBuffer_t`。继续确认 `CmdList` 包含重复 `CmdItem`，其字段 2 又是 `SKBuiltinBuffer_t`；命令编号对应什么聊天事件还未还原。解析结构存在不等于已挂接真实接收链，更不等于已经解析目标群消息。

当前可复现产物包含 63 个函数记录、8 组虚表候选。该数量只是研究覆盖范围，不代表 63 个已验证接口。

### 持续观测（v3 起）

- `--continuous` 使用 `seconds=0`，挂接成功后立即返回，没有自动超时，也不保留等待线程。持续到显式停止或当前微信进程退出。不会自动启动微信、重新登录或注入新的微信进程。
- `--status` 只读取状态；`--stop` 调用自建模块的停止入口，恢复原函数入口。停止后代码和跳板仍保留至微信退出，避免在途回调访问已释放代码。
- `--watch-status` 是隐藏运行的本机采集器，每 2 秒保存状态；计数或阶段发生变化时写入 `.local/native-observer-events.jsonl`。状态文件原子替换，事件日志不含群标识。重复采集器通过进程对应的文件锁拒绝启动。客户端退出后采集器结束。
- 原生模块仅对 `WXPAIR1006` 精确匹配的文本读取群标识；本功能是研究观察器，不是已完成的所有群消息接收通道。匹配结果不会自动触发发送。
- 本地面板新增持续观测状态、计数和“停止原生观测”按钮。超过 12 秒未更新时显示状态待检查，避免把旧快照当成运行证明。停止接口受已有本机 Host、Origin 和 CSRF 校验保护。
- v3 自建子进程验证覆盖持续启动、主动停止、重新开启和正常退出；加载器要求同一 DLL 哈希的持续停止测试通过后才可接入微信。
- 2026-10-06 21:45:01，v3 已在 PID 20424 的微信中开启持续观测。采集器已独立后台运行。运行状态以面板及 `.local/native-observer.json` 最新快照为准，不能把该时间点的启动记录视为永久在线证明。
